Профайл пользователяКто я: Начинающий разработчик Telegram Mini Apps и мобильных приложений.Как мне объяснять: Объяснять максимально просто, как самому первому нубу на свете. Привязывать инструкции строго к точным надписям и элементам, которые видны на экране. Без заумной терминологии. При ошибках вести подробно по окнам.Мои требования к работеПриложение должно работать круглосуточно 24/7 без моего компьютера.Все сервисы для хостинга сайта и запуска бота должны быть абсолютно бесплатными.Процесс не должен требовать привязки банковских карт (особенно зарубежных).Весь рабочий код должен быть надёжно сохранён в облаке GitHub в качестве резервной копии.Что мы уже сделали по проекту tg-miniappЭтап 1. Хостинг сайта портфолиоПеренесли файлы сайта из локальной папки D:/Projects/tg-miniapp в облачный репозиторий на GitHub.Полностью ушли от локального сервера http.server и утилиты ngrok.В настройках репозитория в браузере (раздел More -> Settings -> Pages) включили функцию GitHub Pages для ветки main.Получили постоянный бесплатный круглосуточный адрес сайта вида: github.ioЭтап 2. Настройка и безопасность бота в CursorОткрыли проект в редакторе Cursor.В файле bot.py нашли переменную WEB_APP_URL и заменили старый адрес от ngrok на новую постоянную ссылку от GitHub Pages.Из-за того, что репозиторий на GitHub был опубликован как Public (публичный), скрыли прямую запись токена в коде через конструкцию os.getenv для защиты от кражи.Зашли в Telegram к BotFather, аннулировали скомпрометированный токен через команду Revoke и получили абсолютно новый безопасный токен бота.Прописали новый токен в код bot.py. Бот успешно протестирован локально, все кнопки Mini App работают.Какие ошибки мы исправили в процессеОшибка 1. Сбой указателя HEAD в Git ( reference broken )Суть проблемы: При попытке сделать Commit и Push для соседнего проекта auto_control в программе GitHub Desktop вылетала системная ошибка, блокирующая отправку. Повредился внутренний скрытый файл HEAD на диске.Как исправили: Через проводник Windows зашли в скрытую папку проекта .git/refs/remotes/origin/ и вручную удалили повреждённый файл HEAD. После этого GitHub Desktop автоматически пересоздал чистый рабочий указатель, и отправка заработала.Ошибка 2. Ошибка блокировки портов на Render.comСуть проблемы: При попытке развернуть бота на бесплатном сервере Render.com в режиме Background Worker, сервис выдал всплывающее окно Add Card с требованием привязать банковскую карту для верификации и списания 1 доллара.Решение: Отказались от использования Render, так как это нарушает требование бесплатности и работы без карт.Ошибка 3. Ошибка блокировки сети на PythonAnywhere ( ClientConnectorError )Суть проблемы: Загрузили файл bot.py на бесплатный хостинг PythonAnywhere. При запуске через консоль Bash бот упал с ошибкой Cannot connect to host api.telegram.org:443. На бесплатном тарифе этого сервиса заблокирован доступ к любым внешним сайтам, включая сервера Telegram. Из-за этого в самом Телеграме при нажатии на кнопку вылетал технический экран с розовым единорогом GitHub.Решение: Бот на PythonAnywhere остановлен. Проект готов к переносу на альтернативную бесплатную платформу.Текущая задачаНам нужно запустить готовый файл bot.py (в котором прописан рабочий токен в кавычках и ссылка на GitHub Pages) на полностью бесплатном сервере, который не блокирует сеть Telegram и не требует банковских карт при регистрации.
